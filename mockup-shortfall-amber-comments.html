4 · What this build entails

  • Amber state — change the shortfall logic so cells distinguish "would have been short without this month's PO arrival" (amber) from "still short even with the PO" (red). Late-arriving POs never downgrade red to amber. No DB change, just a smarter computation.
  • Arrival pill — render the matching PO quantity in any amber/red cell where a PO lands that month (or where one is on the books but too late). Hover shows PO number(s). Replaces the separate "Arriving (POs)" row that currently lives below each ingredient/packaging row (or keeps both, your call).
  • Monthly shortfall strip — new 12-column block under the top tiles. For each month, count of (entities short) / (entities with demand that month). Colour: red when any shortfall, neutral when clean.
  • Cell comments — new DB table demand_cell_comments with entity_type ('ingredient' | 'packaging' | 'product'), entity_id, year_month, comment, changed_by, changed_at. Each cell gets a "+" on hover; clicking opens a popover with the comment field + the full history for that cell. Filled comments show a small blue dot in the corner so you can see at a glance which cells have notes.
  • Scope — all four changes apply identically to Ingredient demand, Packaging demand and Production. For Production, "arrival pill" = planned production for that month (we already factor it into the balance), so amber = "production planned this month is what saves it".
