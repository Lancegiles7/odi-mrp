User management — proposal

In-app screens to invite, manage, and remove users. No more Supabase dashboard work.

What's already in place (we don't have to build this)
  • ✓ user_profiles table with role + active/inactive — exists since day 1
  • ✓ Five roles defined with full database-level permission policies (RLS) — see below
  • ✓ Sidebar already gates by role — non-admins don't see settings, users, trash, etc.
  • ✓ Invite email callback — when a user clicks an invite link, they're routed to /reset-password to set their password
  • ✓ Header shows current user + role and has a logout button

The pain last time was that we had to do all this in the Supabase dashboard. The plumbing is sound — we just need the screens.

What we'd build
  1. Settings → Users — list page with name, email, role, status, last sign-in
  2. Invite user button → modal with full name, email, role. Sends an invite email via Supabase.
  3. Edit user page — change role, deactivate, resend invite, danger-zone delete
  4. My profile — every user can edit their own full name & password
  5. Deactivate vs delete — soft-deactivate preserves audit history ("Atma created this PO"); hard-delete only available when no records reference them
The five roles (already defined in the database)

When you invite a new user you pick one of these. Permissions are enforced at the database level — you can't accidentally over-share.

Role Can do Typical user
Admin Everything. Manage users, edit settings, all reads + writes. Owner / you
Operations Read everything. Edit products, BOMs, production plan, ingredients. Production manager
Supply chain Read everything. Edit ingredients, suppliers, raise + receive POs. Purchasing / planner
Finance Read everything. Raise POs (no delete). View costs & reporting. Accountant / CFO
Read only Look but don't touch — view-only across the whole system. External advisor / board
The role names & permissions above are locked in by the database policies. If you ever want to tweak them (e.g. give Finance the ability to delete POs), that's a separate small change — but the five-role split as-is covers most teams.

What the invitee sees
  1. You click "Invite user", fill name/email/role, hit send.
  2. They receive an email from Supabase: "You've been invited to Odi MRP — click to set your password."
  3. They click the link → land on the existing /reset-password page (already built).
  4. They set a password → land on the dashboard, signed in, with the role you assigned.
  5. Their row in the Users page flips from "Invited" to "Active" on first sign-in.
One small prerequisite: Supabase's "invite user" API needs a service role key set as an environment variable in Vercel. I'll send you the 30-second instructions when we're ready to deploy — it's a paste-one-string-into-Vercel job, no code change. Without it, the screens still work for editing existing users but the invite button can't email new ones.
A few decisions before I build
  • • Five roles as-is, or tweak? The current split (admin / operations / supply chain / finance / read-only) is what the DB enforces today. Happy to change permission boundaries but that's a small extra job.
  • • Self-service role change? By default, users can't change their own role — only admins can. Good?
  • • Delete behaviour: when a user is hard-deleted, what they created (POs, products, ingredient edits) stays in the system but the "created by" credit becomes blank. Alternative: block delete entirely if they've created anything (recommend deactivate instead). I'd go with block + force-deactivate — safer.
