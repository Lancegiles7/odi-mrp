Receive screen — Lot #, Expiry & COA

Proposed redesign of the PO receive screen. The single free-text “Note” box is split into a dedicated Lot # field and an Expiry date-picker, and each line gains a COA (Certificate of Analysis) file upload. A free-text note remains for anything else (QA, backorder).

Today
One Note box per line — lot, expiry and any comment all typed together:
Lot #: 260725 Expiry: 9.2.29

Not sortable, not searchable, no way to flag expiring stock, nowhere to keep the COA.

Proposed
Structured Lot # + Expiry + attached COA, with a short note for the rest.

Captured against the stock movement, so we can later search by lot, warn on approaching expiry, and open the COA from the receipt history.

What changes behind the scenes

  • Lot # and Expiry become real fields on the receipt (stock movement), alongside the existing note — so they’re searchable and reportable.
  • COA files are stored using the same documents mechanism already used for ingredient documents, attached to the receipt/lot.
  • Expiry warning (amber) is a nice-to-have: flag lots within a configurable window. Can be left out of round one.
  • Existing receipts are untouched — their combined lot/expiry text stays in the note field as-is.
Open question for you: can a single delivery line arrive as more than one lot (e.g. 400 kg split across two batches with different expiries)? If yes, we’d add a “+ split into lots” option per line. If one lot per line covers it in practice, we keep it simple.
