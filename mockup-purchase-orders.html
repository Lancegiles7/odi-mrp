What needs to change underneath

Schema (one new migration)

  • Add suppliers.payment_terms (text) and suppliers.lead_time_days (int).
  • Make purchase_order_lines.ingredient_id nullable; add product_id (nullable FK) and description (free text). Constraint: exactly one of the three is set per line.
  • New app_settings columns: company_legal_name, nzbn, gst_number, address_lines. (For PDF letterhead.)
  • Auto-numbering trigger or app-level for po_number in the format PO-YYYY-NNN.

New pages

  • /purchase-orders — list (with filters)
  • /purchase-orders/new and /purchase-orders/[id] — create / edit / view
  • /purchase-orders/[id]/receive — receiving flow
  • /api/purchase-orders/[id]/pdf — generates the PDF on the fly (using @react-pdf/renderer or Puppeteer)
  • /suppliers + edit — minimal CRUD so you can manage payment terms, contacts, etc. (Sidebar link already exists.)
  • Settings → "Company info" tab — for NZBN/GST/address used on the PDF

Ingredient demand integration

  • New "Arriving" row added to each ingredient — sums quantities from PO lines with status submitted or partially_received by their expected_delivery_date's month.
  • "Running balance" row replaces the simple shortfall logic, factoring in arrivals.
  • On receipt, the line stops contributing to "arriving" and the received qty becomes part of inventory (via stock_movements).

Open questions for you

  • NZBN, GST number, full company address — what should the PDF show? (I've used placeholders.)
  • Currency — assuming NZD on PDFs. Mixed-currency POs needed?
  • Email-to-supplier button — send via SMTP from the app, or just generate a draft you copy/paste? (First is bigger build.)
  • Multi-line "other" — allowed, or only one "other" per PO?
