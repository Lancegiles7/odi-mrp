Price change tracker — proposal

One record of every price change across ingredients, packaging, finished goods and PO lines — with a master log and a history panel on each item. Nothing here is built yet.

1 · What we have today

Ingredients already keep a price history. Nothing else does.

2 · The one decision that matters: where the tracking happens

Log it in the app

What the ingredients history does now: each save writes a history row alongside.

Problem: it only catches changes that go through that one screen. We can already see the leaks.

Log it in the database ← recommended

The database itself writes a history row whenever a price column changes, no matter what changed it.

Nothing can bypass it — screens, imports, FX updates, or SQL run by hand.

Two leaks that exist right now, in the ingredient history we already have
  • · Changing the FX rate in Settings re-prices every ingredient and every packaging item, and writes no history at all. The loaded costs silently move.
  • · No ingredient price change has been logged since July — either nothing changed, or it changed through a path that doesn’t log. Today we can’t tell which.

5 · Three things to decide before building

A
Do we track the price you agreed, the landed cost, or both?

The agreed price only moves when a supplier changes it. The landed cost also moves every time FX moves. Suggest both, tagged, with FX collapsed in the master view.

B
Should a price change ask for a reason?

A one-line note at save time (“supplier increase”, “correcting a typo”) is what makes the log worth reading in six months. It also adds a step to every save.

C
History starts the day we switch it on.

Past changes can’t be recovered — the old values were overwritten. We’d seed a starting row for every item at today’s price, and carry across the 102 ingredient rows we already have.

Build order if approved: database table + triggers (SQL run by hand first, per the usual process) → master tracker page → history panel on packaging and products → reason prompt. Roughly one migration and three screens.
